# RX400h Protocol Probe V0.1.7

本版把 V0.1.5 已验证的 CAN 11/500 链路改造成可持续显示的基础实时仪表，同时加入独立、低频的 Toyota ECU 白名单探测。

## 主要功能

### 1. 实时基础仪表
- RPM：约 4 Hz 目标调度
- 车速：约 3 Hz 目标调度
- 冷却液温度：约 0.7 Hz
- OBD 口 12V：约 0.3 Hz
- 所有请求严格串行；真实频率受 ELM/ECU 响应时间限制
- 读取失败时保留最后有效值，并显示 `STALE / TIMEOUT / NO DATA`
- 使用单调时钟计算数据年龄，修复上一版 age 异常
- 显示发动机 `OFF / ROTATING — FUEL STATUS UNKNOWN`

### 2. 连接恢复
- 实时模式中连续通信异常后关闭旧连接
- 采用 1、2、5、10、30 秒退避尝试重新连接
- 重连后重新初始化 ELM、锁定最佳协议并复核 `0100`

### 3. 两种模式隔离
- “链路确认”：仅验证 SP6 与 AUTO，不持续采样
- “开始实时仪表”：长期循环读取标准数据
- “Toyota探测”：暂停实时模式，串行测试 `7E0 / 7E2` 下的：
  - `221001`
  - `221002`
  - `221814`
- 探测结束或异常后恢复 CAN 11/500 与功能寻址，再返回实时链路
- 本版不发送动态 DID `2C` 命令

### 4. 日志
- 保留完整 TX/RX、事务状态、延迟、Header、错误与事件标记
- 实时模式每秒写入一帧摘要
- 一键封包并调用 Android 系统分享

## 推荐测试顺序
1. 车辆 P 挡、READY。
2. 连接 OBDLink MX+。
3. 点击“链路确认”，确认 CAN 11/500。
4. 点击“开始实时仪表”，至少运行 10–20 分钟；条件允许可持续 1 小时。
5. 停止实时仪表后点击 “Toyota探测”。
6. 点击“结束并发送所有日志”。

## 当前限制
- 通信仍由 Activity 内的单线程运行；已支持横竖屏切换，但尚未迁移为 Android 前台服务。系统强制结束应用时，实时读取仍会停止。
- Toyota 专用数据尚未解码；SOC、HV 功率、HV 温度显示为 `NOT MAPPED`。
- 本版本的 Toyota 探测目标只是获取第一条合法 `62xxxx` 或 `7F22xx` 响应。

## V0.1.7 重点

- 保留 V0.1.6 的长期实时基础仪表。
- Toyota 探测按 Hybrid Assistant APK 中的 ECU 地址线索调整为：`7E3 → 7E1 → 7E4 → 7E2 → 7E0`。
- 每个 Header 首先只测试白名单：`221001 / 221002 / 221814`。
- 只有 Header 确实返回正响应或合法负响应时，才追加测试 APK 中另外两个已知请求：`220103 / 221F07`。
- 完整解码 UDS Negative Response Code；`7F 22 xx` 会标记为“ECU 已到达”，不再等同于 NO DATA。
- 所有请求保持严格串行，并显著增加 Header 切换、请求及 ECU 响应等待时间。
- 探测完成后恢复 `ATSP6` 和标准实时仪表链路。
- 本版仍不发送 `2C` Dynamic DID 定义；先确认正确 ECU 拓扑，再进入 F301/F302。
